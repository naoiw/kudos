# Kudos

サイクリング・ウォーキング・ゴルフのアクティビティを記録・表示する複数ユーザー対応Webアプリです。

**公開URL:** https://naoiw.github.io/kudos/

## 現在の開発範囲

- [x] Running Page の Dashboard をベースにしたReact/TypeScriptフロントエンド
- [x] 日本語UI、英語のソースコードコメント
- [x] GitHub Pages のプロジェクトパス `/kudos/` 対応
- [x] 架空のサンプルデータ（実際のGPS・個人情報は含まない）
- [x] Google Drive + Apps ScriptによるGPX/TCX取り込み、Sheets管理と明示的なJSON公開
- [x] 公開JSONからの複数ユーザー読み込みとユーザー切替
- [ ] Google認証とユーザー単位の閲覧制限
- [ ] 公開経路のプライバシーフィルター

## ローカルで起動

Node.js 22以降とpnpm 8.xを使用します。

```bash
corepack enable
pnpm install
pnpm dev
```

## GitHub Pages

`main`へのpushで `.github/workflows/deploy.yml` がビルドとデプロイを行います。
GitHubリポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** に設定してください。初回はリポジトリのPages設定が必要な場合があります。
ビルド時は `PATH_PREFIX=/kudos` により静的アセットの基準パスを設定します。

## データの扱い

`src/static/activities.json` は初期画面を確認するための完全な架空データです。
現段階では認証機能はありません。個人の実際のGPX・GPS軌跡・位置情報は**絶対に公開リポジトリへコミットしないでください**。

## 日本地図（足跡マップ）

元の [running_page](https://github.com/yihong0618/running_page) の「足跡マップ」と同様に、React + SVG で都道府県ごとの訪問状況を描画します。クリックすると対象都道府県のアクティビティに絞り込みます。

地図は中部地方を中心に初期表示し、ドラッグで移動、マウスホイール／タッチのピンチ操作と画面上の＋／－ボタンで拡大縮小できます。都道府県を選択すると（未訪問の都道府県を含む）主な陸地が中央へ移動し、ズーム操作中も表示中心を保ちます。「戻す」で絞り込みを解除して初期表示へ戻せます。

- 地図データ：[hfu/gmjpn21pref](https://github.com/hfu/gmjpn21pref) の日本47都道府県 GeoJSON（Unlicense / Public Domain）
- 原典：国土地理院「地球地図日本」（[国土地理院ウェブサイト](https://www.gsi.go.jp/kankyochiri/gm_jpn.html)）
- ランニングとサイクリングでフィルター可能
- 現在の件数判定：活動データの `location_country` に記載された都道府県名
- 将来対応予定：GPXの経路が通過した複数都道府県の自動集計

ルートマップの背景タイルはライト・ダークの両モードでグレースケール化します。経路色は種目に応じて残します。

## GPX/TCX取り込み基盤（Apps Script）

複数人のGoogle Driveフォルダを巡回して、1アクティビティ1行で非公開Google Sheetsへ取り込む仕組みを `gas/` に追加しています。初期セットアップと設定方法は [gas/README.md](gas/README.md) を参照してください。

公開サイトは、明示的に承認・Publishされた公開JSON（現在は`schema_version=2`）を読み込みます。元GPX/TCXが自動公開されることはありません。

## Sheetsの統計プレビュー（ユーザー切り替え）

管理用Google Sheetsの活動をKudosへ表示するため、GASに `publishApprovedPublicPreview()` を用意しています。管理者が手動実行すると、距離・種目・運動時間のほか、**Usersの表示名とDriveのGPX/TCXから生成した経路**を `public/data/preview.json` に書き出します。

- 公開サイトのユーザー切り替えは `?u=u01`、`?u=u02` などのURLで利用できます。
- 未承認の場合は従来の架空データを表示します。
- 公開する統計情報は**インターネット上の誰でも閲覧可能**です。
- 表示名とGPSルートは含まれます。メールやDriveのファイルIDは含めません。日時は従来の設定に従います。
- 現在のGitHub Pagesは公開サイトのため、GPX経路は誰でも閲覧できます。非公開運用する場合は認証と権限制御が別途必要です。

詳細な設定は [GASセットアップ手順](gas/README.md#7-ウェブ画面へ統計プレビューを反映する手動公開許可制) を参照してください。

## GPX取り込みと足跡マップの自動判定

- GASで `importNextManualBatch()` を複数回実行すると、DriveのGPX/TCXを実行時間制限の範囲で順次取り込みます。既存ファイルは重複登録せず、再開位置を保持します。定期実行は明示的に有効にするまで不要です。
- GPXの経路から47都道府県の境界と交差する地域を判定し、足跡マップへ訪問状況を反映します。
- 都道府県の選択でアクティビティを絞り込み、ルートマップも選択地域内の走行箇所へフォーカスします。
- [GAS取り込み・更新手順](gas/README.md#未取り込みgpxの手動一括処理定期実行なし)

### 大量GPXの公開は分割実行

GASの公開処理は実行上限を超えないよう、`05_PublicPreview.gs` + `06_BatchedPublish.gs` の分割処理に変更しました。`publishApprovedPublicPreview()` を繰り返し手動実行して全件の経路Blobを準備し、最後に1回だけ `main` の `preview.json` と経路チャンクを更新します。スケジュールは無効のままです。公開中のサイトは最終コミットまで以前のデータを表示します。

詳しくは [GAS公開処理の手順](gas/README.md#7-4-大量gpxの分割公開2026年11月更新) を参照してください。

## アクティビティ種目

Kudosの種目は**サイクリング・ウォーキング・ゴルフ**の3種類（表示順も同じ）です。アクティビティの名前を優先してキーワード判定し、判断できないものはGPSや従来の種類推定を利用します。以前の `Run` もウォーキングに統一します。

既存の公開済みデータはブラウザ側で互換分類するため、GPS経路の再Publishは必要ありません。管理シートを統一する場合はGASの `applyActivityOverrides()` を1回実行してください。詳しくは [GAS手順](gas/README.md#9-アクティビティ種目の判定サイクリングウォーキングゴルフ) を参照してください。

## GASソース同期（clasp）

GitHubの`main`をGASソースの正本とし、[Issue #23の手順](docs/gas-clasp-sync.md)に従って`clasp`で**明示的に**既存Apps Scriptプロジェクトへ同期します。CIには手動起動専用の`Sync Kudos Apps Script source`を追加しています。通常のPR・`main`へのpushではGASに反映されません。認証情報・Script ID・Script PropertiesはGitへ保存しません。**定期GASトリガーは無効のまま**です。

## 種目分類ルールの管理（Issue #21）

種目の別名、タイトルキーワード、優先順位は[`shared/sport-rules.json`](shared/sport-rules.json)が正本です。TypeScriptはJSONを直接読み込み、GASは`gas/00_Config.gs`に埋め込んだ自動生成済み定義を使います。

ルールを編集した場合は`node scripts/generate-sport-rules.cjs`を実行し、生成されたGASの変更もコミットしてください。CIと`node scripts/verify-gas-sync.cjs`は生成済み定義の整合性を検査します。GASとTypeScriptの一致は`shared/sport-contract-cases.json`を使用した契約テストで確認します。詳しくは[`docs/sport-rules.md`](docs/sport-rules.md)を参照してください。

## 公開アクティビティID（Issue #16）

GASの公開`run_id`は、Sheet内の非公開`activity_id`から決定する48bit数値IDです。名前・日時・並び順・ユーザーの公開順を変更しても維持されます。旧`schema_version=1/2`の数値IDもフロントエンドでそのまま読み込めます。詳細は[`docs/stable-activity-ids.md`](docs/stable-activity-ids.md)を参照してください。

本番の公開データは、自動では書き換えません。GitHubへのマージ後に管理者が明示的にGASへclaspで反映し、その後必要に応じて手動で再Publishします。

### 公開日時と統計の精度（Issue #17）

公開データの`date_precision: month`は年月のみを示します。ヒートマップ・カレンダー・週別/日別の集計や連続記録は表示しません。`exact`モードでは正確な活動日時を表示できますが、公開対象者の同意と別途の明示的な承認が必要です。手順は[`docs/date-precision.md`](docs/date-precision.md)を参照してください。

## 種目別目標の設定

ホーム画面の「目標設定」から、表示ユーザーごとにサイクリング・ウォーキング・ゴルフの**年間／月間距離目標（km）**を変更できます。初期値は以下のとおりです。

| 種目 | 年間 | 月間 |
| --- | ---: | ---: |
| サイクリング | 2,000 km | 150 km |
| ウォーキング | 250 km | 20 km |
| ゴルフ | 10 km | 1 km |

「すべて」フィルターでは3種目の目標を合算します（年間2,260 km、月間171 km）。週間目標は月間目標から12か月÷52週で換算した参考値です。アクティビティ実績の距離は各種目の活動データを合計します。

初期値の正本は`config.yml`です。画面から変更した値は`localStorage`に**表示ユーザー単位・ブラウザ単位**で保存し、他の端末には同期しません。公開JSON、GAS、GitHubの設定を変更するものではなく、ほかの閲覧者の目標も変更しません。「初期値に戻す」でそのブラウザの個別設定を削除できます。

## 年・種目フィルターの共通化

ホーム、ルート一覧、集計で、上部の種目ボタンとその直下の年ボタンを共有します。表示ユーザーの全データから年の候補を作成し、`すべての年`か特定の年を選択すると、活動履歴、ヒートマップ（日時を日単位で公開する場合のみ）、プロフィール、GPS経路、足跡マップ、カレンダー、ルート一覧、集計ページの対象活動が同時に切り替わります。従来の各ウィジェット内の年選択UIは削除しています。

年切替時は表示中の活動・都道府県選択を解除し、前の年の経路が残らないようにします。年間目標カードは選択年を集計し、月間カードは選択年における現在と同じ暦月を集計します。`すべての年`のとき年間・月間目標はそれぞれ現在年・現在月、ほかの統計は全期間を表示します。年フィルターは閲覧用で、公開JSONやGASのデータは変更しません。

## 国・都道府県の訪問実績

プロフィールカードの訪問国・都道府県の件数は、足跡マップと同じ`prefecturesForActivity()`でGPX/TCX経路の通過地点から集計します。同じ地域に何度訪問しても1件として数えます。日本の都道府県を経路から確認できた場合は、国の件数にも「日本」を1か国として反映します。公開JSONの`location_country`がすべて`null`でも動作します。

年・種目選択に応じて訪問実績も更新されます。手入力の国情報がある場合はそれも使用します。国外のGPS経路だけから国名を逆引きする処理はまだないため、その場合は国数に計上しません。GASや公開JSONの変更・再Publishは不要です。

## 海外のGPSと世界の足跡マップ

足跡マップ上部から「日本（都道府県）」と「世界（国・地域）」を切り替えられます。世界モードはGPS経路を国・地域の境界と照合し、訪問した国・地域を強調表示します。地図上の国・地域または訪問地域のボタンを選択すると、活動履歴・GPSルートマップ・カレンダーが連動して絞り込まれます。年・種目フィルターとも連動します。

- 世界境界：Natural Earth（1:110m Admin 0 Countries）、小島・小規模地域：Natural Earth（1:50m Tiny Countries）。パブリックドメイン。`src/assets/world-countries.json`へ必要な境界と表示名のみを格納しました。
- 判定：各公開GPS経路の座標が国・地域のポリゴンに含まれるかを確認します。小島など粗い境界に含まれない地域は代表点の周囲を概略判定します。国境近辺や小島の細部では誤差があり得ます。
- 日本の都道府県実績は従来の精密な日本地図で判定し続けます。国外については国・地域単位で表示し、他国の州・県を日本の都道府県数には加えません。
- `location_country`が`null`でもGPS経路から判定できます。国・地域名の直接指定がある場合は補助情報として利用します。
- この実装はフロントエンドのみです。GASの設定変更・GPSの再Publish・外部の位置情報APIへの送信は不要です。

## 種目別の統計表示（Issue #22）

共通の種目選択に応じて、年間目標カード・集計ページ・アクティビティ履歴で意味のある指標と単位を使います。

| 対象 | 主な指標 | 速度・ペース表示 |
| --- | --- | --- |
| サイクリング | 距離、活動時間、獲得標高、回数、年間・月間目標 | 移動距離÷活動時間の平均速度（km/h） |
| ウォーキング | 距離、活動時間、回数、最長連続活動日数、年間・月間目標 | 移動時間÷距離の平均ペース（分/km） |
| ゴルフ | 活動回数、歩行・移動距離、活動時間、年間・月間目標 | 非表示（スコアやラウンド数は推測しない） |
| すべて | 3種目の件数、合計距離・時間・獲得標高、合算した目標 | 異種目を混ぜた平均速度・ペースは非表示 |

ゴルフ活動の総距離はGPX/TCXに記録された移動距離です。実際のラウンド回数や打数、スコアは活動データに存在しないため表示しません。活動履歴の10/20/40 kmしきい値はゴルフ単独時には非表示にします。日単位の正確な日時を公開しない設定ではウォーキングの連続活動日数も表示しません。集計関数は`src/core/sportMetrics.ts`を共通利用し、テストは`scripts/tests/sport-metrics.test.cjs`で確認します。
