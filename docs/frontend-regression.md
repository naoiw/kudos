# フロントエンド回帰確認

Kudosのフィルター・集計・地図・カレンダーを変更したときに、既存の動作を維持できているか確認するための一覧です。テストの実行環境と手動確認の担当範囲を分けています。

## 自動テストとビルド

GitHub Actionsの[Validate Kudos](../.github/workflows/check.yml)は、`main`宛PRごとに以下を検査します。

- Linux（Node.js 22）：pnpmの依存解決、Viteビルド、種目ルール生成確認、GASのclasp同期対象検証、GAS＋フロントのNodeテスト、実際の`clasp show-file-status`のファイル選択検査（認証はしない）。
- Windows（Node.js 22）：CRLFチェックアウト、GAS生成ルール・ソース整合性、Windows上の生成処理テスト。

ローカルでの主要な検証：

```bash
corepack enable
pnpm install --frozen-lockfile
node scripts/generate-sport-rules.cjs --check
node scripts/verify-gas-sync.cjs
node --test gas/tests/*.test.cjs scripts/tests/*.test.cjs
PATH_PREFIX=/kudos pnpm build
```

既存のNode標準テスト、TypeScriptの`transpileModule`、Reactのサーバーレンダリング／要素とコールバック実行、HTTPスタブを活用します。**ブラウザ上での自動E2Eテストではありません。** 実際の地図操作やレスポンシブ表示は次の手動項目で確認してください。

## ブラウザでの確認

1. **初期表示とユーザー：** ホームを直接開き「すべての種目＋最新の活動年」になっていることを確認。ユーザー切り替え後に統計・履歴が切り替わり、URLの`?u=`も更新されることを確認。
2. **共通フィルター：** 種目（Ride／Walk／Golf）と年（特定年／すべての年）を切り替え、統計、ヒートマップ、活動履歴、プロフィール、足跡マップ、ルート表示が一致することを確認。以前に選んだ経路が別条件に残らないこと。
3. **集計ページ：** 直接開く／ヘッダーから移動すると「Life＋すべての年」になること。期間は「Life→年→月」の3つのみ。Life中に年を直接選べば「年」へ切り替わること。Rideはkm/h、Walkは分/km、Golfは移動・歩行距離であり、心拍数が表示されないこと。
4. **カレンダーの上下限：** 選択ユーザーの最古の活動月まで戻れること、それより前は戻れないこと。今月まで進めること、来月へは進めないこと。種目・地域で絞っても最古月の境界が変わらないこと。
5. **カレンダーの年またぎ：** 2026年1月→前月で2025年12月、その逆も成立し、上部の選択年が移動先に追従すること。「すべての年」から操作した場合はそのまま維持されること。
6. **日付とルート：** 同日に複数活動があるカレンダー・ヒートマップの日付をクリックし、開始時刻が最も早い活動が地図に表示されること。日別一覧から2件目も選択できること。
7. **ヒートマップの未来日：** 今年を選んだとき、当日までは通常表示、翌日から12月31日までは薄く表示され、押しても地図や日別一覧が変化しないこと。過去年は全日通常表示、「すべての年」でも今年の未来日だけ薄くなること。ライト／ダーク、画像書き出しでも表示が一致すること。
8. **足跡マップ：** 日本と世界を切り替え、都道府県・国／地域を選ぶと活動とGPS経路が絞り込まれること。日本の地図はドラッグ・ズーム・選択地域への移動と解除が機能すること。
9. **ルート密度：** ホームで「通常／密度」を切り替え、繰り返し通った区画が青・橙・赤で表示され、凡例と一致することを確認。個別活動を選んだときは通常ルートに一時的に戻り、解除したら密度に戻ること。種目、年、都道府県／国・地域、ユーザーを切り替え、以前の選択対象の密度が残らないこと。大量のGPS経路、無効経路、ゼロ件、Worker失敗時の再試行、画面全体表示、ズーム、ドラッグ、スマホ操作を確認。生活圏推定の注意書きがあること。
10. **地図の出典表示：** 通常表示ではLeaflet標準の右下クレジットを出さず、地図下のフッターに「Map data from OpenStreetMap」と表示し、「OpenStreetMap」の文字だけがライセンス情報へリンクすること。「背景地図 · OpenStreetMap」と二重表示されないこと。全画面では地図内右下に移動し、フッター側と二重表示されないこと。通常／密度、ライト／ダーク、スマホ幅でも読みやすく、クリックでOpenStreetMapの著作権・ライセンス案内に移動できること。
11. **比較ページ：** ユーザー2人以上を選び、Life／年／月と種目フィルターを切り替えて同期間の件数・距離・時間・都道府県数が正しいことを確認。比較ページでは年候補に全ユーザーの年が出ること、月変更が全ユーザーに作用すること、片方に活動がないと0表示になること、1人以下では比較を案内すること。ブラウザ再読み込みや戻る／進む、スマホの横スクロールとライト／ダークも確認。
12. **表示・操作：** PCとスマホ幅で、ナビ、フィルター、地図、横スクロール、キーボードEnter／Spaceによる選択を確認。ライト／ダークで文字・経路が見えること。狭い画面では活動選択時に地図へ移動すること。
13. **`date_precision=month`：** 日別カレンダーとヒートマップが表示されず、集計はLife／年／月のみで月別の日別グラフを表示しないこと。比較ページでも月単位の記録を正しく合算し、日別の推移を描かないこと。架空の日付・時刻が現れないこと。
14. **公開データ異常系：** `preview.json`がない／未承認の場合は架空デモを表示すること。公開v2 manifestのチャンクが欠落・不正な場合は黙ってデモ経路に置き換えないこと。実際の公開データをテストのために壊してはいけません。

## オンラインプレビューの検証

`develop`のCI成功後、以下をスマートフォンとPCで確認します。

- 本番 `https://naoiw.github.io/kudos/` は本番のコード、プレビュー `https://naoiw.github.io/kudos/develop/` は`develop`のコードを表示すること。本番に未マージ機能が現れないこと。
- プレビューで`/tracks`・`/summary`へ移動し、直接URLを開き直しても`/kudos/`の本番画面へ戻らないこと。
- 本番・プレビューともに同じ`main`承認済み`public/data/preview.json`と`route_chunks`を読み、経路や統計が正常表示されること。未承認GPSやシート情報を含まないこと。
- `develop`へのpushで`Validate Kudos`が成功した場合のみデプロイWorkflowが動き、GitHub Pagesの`build`／`deploy`が成功すること。
- ヒートマップの今年の未来日が薄くなり選択不可になる修正が本番・プレビューで継続動作すること。

## 公開・運用の検証

- 本番へ出す個別機能PRはCI成功後に`main`へマージし、[Pagesデプロイ](../.github/workflows/deploy.yml)の`build`／`deploy`両ジョブが成功していることを確認します。`develop`へのpushもCI成功後に同じPages成果物のプレビューへ反映されます。
- GASの変更がないなら`clasp push`とGPSの再Publishは不要です。GASソース同期を行う場合は、[同期手順](gas-clasp-sync.md)と[Publish手順](../gas/README.md)をそれぞれ参照してください。
- 公開プレビューの現行設定は`exact`ですが、デフォルト設定の`month`も必ずテストに残してください。公開日時とGPS経路の取り扱いは[プライバシー手順](date-precision.md)を参照してください。

## 既知のテスト範囲

Nodeテストは集計関数、React要素の出力と選択コールバック、取得失敗時の処理を検査しています。ブラウザの本当のDOM上でのドラッグ、ピンチ操作、地図レイヤーの配置や見切れ、実機性能は保証しません。必要になったらPlaywright等のE2Eテストを追加検討してください。
