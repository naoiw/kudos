# フロントエンド回帰確認（Issue #24）

## 自動テスト

追加の依存ライブラリやロックファイル更新を避けるため、既存の `node --test` と TypeScript の `transpileModule`、React 19 の `react-dom/server` を使います。ルート取得にはHTTPスタブを渡し、実ユーザーのGPSはテストへ取り込みません。

ローカルでの実行:

```sh
pnpm install --frozen-lockfile
node --test scripts/tests/frontend-behavior.test.cjs
node --test gas/tests/*.test.cjs scripts/tests/*.test.cjs
pnpm build
```

GitHub Actions `Validate Kudos` の Linux job は同じテストとビルドを毎PRで実行します。Windowsでは既存の sport rules と CRLF 検査を維持します。

### 主な自動テスト対象

- 表示ユーザー切替UIのSSR出力、ユーザー選択イベントの通知、日本語・英語ラベル
- 種目と年のスコープ、ユーザー間の活動分離、最新年、空データ
- 月曜始まりのヒートマップ（同日複数件、2023年の日曜開始、2024年の閏日）
- 地図ルートサムネイルのPolyline変換と短い経路の空表示
- 6並列上限でのチャンク読込、重複ID、壊れたJSON、危険なパス、404
- 公開JSON v1・v2、正確な日時と月精度の匿名化、GPS経路保持、ユーザー単位の活動
- v2の経路欠落時に架空デモへ黙って切り替えない契約

## 手動の画面操作チェック

1. ホームを開き、すべての種目＋最新活動年の選択と、表示ユーザー切替が正しいことを確認する。URLの `?u=` に切替先IDが反映されることを確認する。
2. 種目（サイクリング／ウォーキング／ゴルフ）と年（特定年／すべての年）を切り替え、Stats、ヒートマップ、活動履歴、カレンダー、世界／都道府県足跡マップが同じ対象を表示することを確認する。
3. 1日に複数活動がある日付をカレンダーで選び、先頭の経路が選択され、詳細一覧から別の活動も選べることを確認する。
4. 足跡マップで都道府県、世界モードで国・地域を選択し、対象経路の表示に連動することを確認する。
5. ルート一覧・集計ページを切り替え、種目ごとのペース・速度・ゴルフ距離が適切な単位であることを確認する。
6. PCのマウスおよびスマホ幅のタップで、ナビ、ユーザー選択、年と種目、地図操作を試す。横スクロールのはみ出しがないことを確認する。
7. ライト／ダーク切替で地図、文字、選択ボタンが見え、活動一覧のEnter／Spaceで選択できることを確認する。
8. `date_precision=month` のテストデータでは日付の捏造がないこと、日別ヒートマップ・カレンダー・日／週集計が表示されないことを確認する。

### 既知の制限・次の段階

今回の自動テストはNodeでコンポーネントのHTMLレンダリングとイベントハンドラ呼び出しを検証します。ブラウザ実機上のレイアウト・Map UI全体のE2E操作は上記手動項目として残ります。将来DOM環境を用意する場合はVitest＋React Testing LibraryまたはPlaywrightへ移行できます。
